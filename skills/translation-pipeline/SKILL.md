# Translation Pipeline — переводчик сложных документов

## Overview

Многостадийный пайплайн для перевода длинных и сложных текстов (книги, статьи, техническая документация, юридические документы, научные работы) с любого языка на русский.

Архитектура наследует принципы NFP (nonfiction-book-pipeline), адаптированные под перевод:

```
Исходный документ
       ↓
┌──────────────────┐
│  1. Ingestion    │ — извлечение, язык, структура, NER
└──────────────────┘
       ↓
┌──────────────────┐
│  2. Foundation   │ — глоссарий, стиль, реестр сущностей
└──────────────────┘
       ↓
┌──────────────────┐
│  3. Chunking     │ — сегментация на блоки 500–1500 слов
└──────────────────┘
       ↓
┌──────────────────┐
│  4. Translation  │ — параллельный перевод субагентами
│  (2 волны)       │    волна 1: черновик, волна 2: доработка
└──────────────────┘
       ↓
┌──────────────────┐
│  5. Quality Gates│ — термины, целостность, стиль, плавность
└──────────────────┘
       ↓
┌──────────────────┐
│  6. Assembly     │ — сборка, финальная проверка, экспорт
└──────────────────┘
       ↓
  Готовый перевод
```

## When to Use

Используй этот скилл, когда:
- Пользователь просит перевести **длинный текст** (>2000 слов, много страниц, книгу)
- Нужен перевод **с сохранением терминологии** (техническая/юридическая/научная документация)
- Нужен перевод **сложного документа** с структурой (главы, секции, сноски)
- Пользователь хочет не просто машинный перевод, а **качественный, вычитанный** результат
- Исходный документ требует **анализа предметной области** перед переводом

**НЕ используй** для:
- Коротких фраз (используй прямой перевод через LLM)
- Разговорной переписки
- Если пользователь явно просит «просто переведи, без заморочек»

## Pipeline Structure

Все проекты переводов хранятся в:

```
/root/apps/translation-pipeline/projects/<project-slug>/
├── intake.json              # метаданные проекта (язык, объём, тип)
├── source/
│   ├── original.ext         # исходный файл (PDF, DOCX, EPUB, MD, HTML, TXT)
│   └── source.md            # извлечённый текст в Markdown
├── foundation/
│   ├── glossary.md          # двуязычный глоссарий терминов
│   ├── style.md             # стилистические правила перевода
│   ├── entities.md          # реестр имён, топонимов, дат
│   └── intake.json          # метаданные (дублируется на уровень выше для быстрого доступа)
├── chunks/
│   ├── chunk_map.json       # карта сегментов
│   ├── chunk_001.md         # исходный сегмент 1
│   ├── chunk_002.md         # ...
│   └── ...
├── translations/
│   ├── draft/
│   │   ├── chunk_001.md     # черновой перевод сегмента 1
│   │   └── ...
│   └── final/
│       ├── chunk_001.md     # финальный перевод после доработки
│       └── ...
├── quality/
│   └── report.md            # отчёт проверок качества
├── manuscript.md            # полный переведённый документ
└── output/                  # экспорт в разных форматах
    └── translated_document.md
```

## The Process

### Step 1: Intake

Определить параметры проекта:

1. Принять исходный файл (загруженный или по ссылке)
2. Скопировать в `source/original.ext`
3. Извлечь текст → `source/source.md` (pandoc для PDF/DOCX/EPUB, прямое копирование для MD)
4. Определить язык (pycld3 или MiniMax)
5. Структурный анализ: заголовки, количество слов, главы
6. Записать `intake.json`

```bash
pandoc source/original.pdf -t markdown -o source/source.md --wrap=preserve
```

### Step 2: Foundation

Создать базу для перевода:

1. **`foundation/glossary.md`** — таблица терминов source→target:
   - Пропустить MiniMax-субагента по тексту для извлечения терминов
   - Верифицировать вручную (MiniMax review)
   - Формат: `| source | target | domain | notes |`

2. **`foundation/style.md`** — стилистические правила:
   - Регистр (научный, публицистический, официальный)
   - Обращение (ты/Вы)
   - Система транслитерации
   - Запрещённые кальки
   - Особые указания

3. **`foundation/entities.md`** — реестр имён, топонимов, дат:
   - Извлечение через NER или MiniMax-проход
   - Формат: `| original | target | type | notes |`

### Step 3: Chunking

Разбить исходный текст на сегменты:

1. Прочитать `source/source.md`
2. Разделить по заголовкам глав/разделов (если есть)
3. Для крупных глав — дополнительно разбить по параграфам
4. Каждый chunk = 500–1500 слов (оптимально 800–1200)
5. Сохранить контекстную информацию:
   - `prev_chunk_id` / `next_chunk_id`
   - Основная тема
   - Ключевые термины в chunk
6. Записать `chunk_map.json` и отдельные `chunks/chunk_NNN.md`

```json
// chunk_map.json
{
  "total_chunks": 12,
  "source_language": "en",
  "target_language": "ru",
  "chunks": [
    {
      "id": "chunk_001",
      "title": "Introduction",
      "chapter": "Chapter 1",
      "word_count": 1100,
      "prev_chunk": null,
      "next_chunk": "chunk_002",
      "terms": ["machine learning", "neural network"]
    }
  ]
}
```

### Step 4: Translation (2-волновая стратегия)

#### Волна 1 — Drafting (параллельно)

Запустить `delegate_task` для каждого сегмента (по 3–5 параллельно):

```python
delegate_task(
    requirements="Переведи текст сегмента chunk_NNN с английского на русский",
    tasks=[...],
    skills=["translation-worker"],
    model="minimax-m2.5",
    provider="minimax"
)
```

Каждый субагент получает:
- Текст сегмента
- `foundation/glossary.md` (глоссарий)
- `foundation/style.md` (стиль)
- `foundation/entities.md` (сущности)
- `chunk_map.json` (контекст: предыдущий/следующий сегмент)
- Prompt с инструкциями переводчика

Результат → `translations/draft/chunk_NNN.md`

**Fallback (если subagents 404):**
Последовательный перевод через `execute_code` с вызовом MiniMax API.

#### Волна 2 — Expansion (доработка)

Проверить черновики:
1. Выявить проблемные места (длина не совпадает, потерян смысл)
2. Для проблемных сегментов — запустить доработку
3. Проверить согласованность терминов между сегментами
4. Результат → `translations/final/chunk_NNN.md`

### Step 5: Quality Gates

Последовательные проверки:

| Gate | Что проверяет | Инструмент |
|------|--------------|------------|
| G1 | Терминология (глоссарий соблюдён?) | Python-скрипт / LLM |
| G2 | Целостность (нет пропусков, все сегменты переведены) | `diff chunk_map vs file list` |
| G3 | Единство стиля (по всему документу) | LLM-проход |
| G4 | Плавность (читаемость на русском) | LLM-проход |
| G5 | Форматирование (разметка, ссылки, структура, чистота) | Python-скрипт |

Результат → `quality/report.md` с баллами и списком проблем.

Если проблемы есть: вернуться на этап доработки.
Если проблем нет: перейти к сборке.

**G5 включает проверку на артефакты номеров строк:**
Субагенты могут включить номера строк из `read_file` в перевод (`1|текст`, `78|...`). Перед сборкой выполнить:

```bash
find translations/draft/ -name '*.md' -exec sed -i '/^[0-9]\{1,3\}|/d' {} +
```

⚠️ Если ВСЕ строки чанка начинаются с `NN|`, это sed удалит всё содержимое. После чистки проверять каждый чанк: `wc -w translations/draft/chunk_*.md`. Пустые чанки переводить заново.

### Step 6: Assembly

1. **Подготовка финальных файлов.** Если `translations/final/` пуста или отсутствует — скопировать чанки из `translations/draft/`:
   ```bash
   mkdir -p translations/final
   cp translations/draft/chunk_*.md translations/final/
   ```
   ⚠️ Это копирование — не замена Quality Gates. G1–G5 всё равно должны быть пройдены.

2. **Очистить артефакты номеров строк** — перед склейкой проверить все `translations/final/chunk_NNN.md` на префиксы `NN|`:
   ```bash
   find translations/final/ -name '*.md' -exec sed -i '/^[0-9]\\{1,3\\}|/d' {} +
   ```
   После: `wc -w translations/final/chunk_*.md` — пустые файлы перевести заново.

3. **Склеить** все `translations/final/chunk_NNN.md` по порядку
3. Финальная проверка структуры (заголовки, оглавление)
4. Сохранить → `manuscript.md`
5. Показать пользователю: `MEDIA:manuscript.md`
6. Скопировать в `/root/outputs/<project-slug>-translation.md`

## Prompt Template for Translator Subagent

```
Ты — профессиональный переводчик. Переведи следующий текст с [SOURCE_LANG] на [TARGET_LANG].

## Глоссарий (обязательно соблюдать)
[glossary content]

## Стиль
[style content]

## Реестр сущностей
[entities content]

## Контекст
Предыдущий сегмент: [prev_chunk_preview]
Следующий сегмент: [next_chunk_preview]

## Текст для перевода
[chunk text]

## Требования
1. Сохрани все Markdown-разметку (заголовки, списки, ссылки, код)
2. Соблюдай глоссарий — термины строго по таблице
3. Имена собственные — по реестру entities
4. Перевод должен читаться как естественный русский текст, а не калька
5. Сохрани тон и регистр оригинала
6. НЕ добавляй комментарии переводчика в текст
7. Верни ТОЛЬКО переведённый текст, без преамбул и пояснений
```

## Emergency Procedures

### Subagent недоступен (opencode-go 404)
- Переключиться на прямой последовательный перевод
- Использовать MiniMax API напрямую через `execute_code`
- Сообщить пользователю, что перевод будет последовательным, а не параллельным

### Превышение контекста
- Уменьшить размер chunk до 500–700 слов
- Для очень длинных книг — переводить по главам

### Исходный документ не читается
- Если pandoc не извлекает текст (отсканированный PDF): запросить у пользователя OCR-версию или другой формат
- Если бинарный формат: попробовать `pandoc -t plain`

### Качество неудовлетворительное
- Если Gates показывают < 7/10: запустить полный повторный перевод с уточнённым глоссарием
- Если проблема в стиле: обновить `foundation/style.md` и перевести проблемные сегменты заново

## Pitfalls

- **Никогда не пропускай Quality Gates** — сборка manuscript.md напрямую из черновиков (draft) без G1–G5 ведёт к несогласованности терминологии, потере ссылок, стилистическому дрейфу и непереведённым фрагментам. Всегда запускай `quality_gates.py` перед assembly. Если gates показывают < 5/5 — дорабатывай, а не склеивай.

- **Артефакт номеров строк:** ...** субагенты, читающие чанки через `read_file`, видят строки с префиксом `1|`, `78|` и могут включить их в перевод. После перевода всех чанков — запустить `sed -i '/^[0-9]\{1,3\}|/d'` по `translations/draft/*.md`. ОПАСНО: если ВСЕ строки чанка начинаются с `NN|`, этот sed удалит весь файл — проверять `wc -w` после чистки.

- **Перевод таблиц:** Telegram-style (пользователь) не поддерживает pipe-таблицы. В исторических/академических текстах таблицы следует конвертировать в маркированные списки с метками (Династия:, Даты:, Примечания:).

- **Согласованность ссылок:** субагенты могут перепутать нотацию ссылок. Все `[N]` из оригинала должны перейти в перевод без изменений. Проверять на этапе G5.

- **Клинопись и спецсимволы:** 𒁹, 𒉏, еврейские и древнеперсидские знаки — не менять, не транскрибировать. Сохранять как есть.
